# Request identity foundation (#182)

**Goal:** Every accepted foreground request gets durable identity before readiness/admission; attempts, capacity tickets, and reviews remain correlated even when no provider runs.

**Design:** Add migration 17 with review_requests, request_links, and bounded execution-history projections. Store request operations live in request_store.py (Store mixin, no new connection). requests.py holds an execution-local ContextVar and a lazily loaded shared service wrapper. A request is execution bookkeeping, never coverage. Idempotency keys are scoped to worktree plus exact captured identity and explicit invocation intent; active duplicates return in-flight, finished duplicates return the original result, changed identity refuses. No active lease is reclaimed to permit duplicate calls. Ordinary compatible checkpoint continuation atomically reclaims its originating unsuccessful request; each execution has its own owner and history entry. Active owners are never stolen; a changed continuation target is refused.

Requested identity records canonical repo, Git common dir, normalized worktree, branch/head/base/diff/tree/config hashes or explicit capture error. Pipeline rechecks that identity under foreground admission before provider work. Request IDs are emitted as progress and returned in service/MCP metadata; default verdict text is preserved. CLI/MCP add an optional request_key for idempotent retries. Store writes link saved reviews and recovery/batch IDs atomically with their artifact. Capacity enqueue links tickets under the current request. Existing prepush reservation IDs remain the authoritative dispatch request identifiers; map them explicitly without altering dedup or queue ordering.
