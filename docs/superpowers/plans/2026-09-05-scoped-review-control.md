# Scoped review control and cancellation audit plan

Goal: close #183 with worktree-local observation and explicit guarded control, preserving request ownership and review trust.

- Add migration18 cancellation_audit through a small ControlStoreMixin: persisted target/request/execution identity, bounded actor/source claims, caller PID/worktree, reason/cause, timestamp, outcome. No migration to existing trust or review state enums.
- Add control.py scope normalization, expected identity validation, bounded local/repository/host status selection, and cancellation lifecycle classification. Explicit IDs may cross worktrees; default scope never does. Multiple active local requests refuse with identifiable candidates.
- Compose RequestCancel with the existing upstream Event. Read durable cancellations for exactly request ID and execution owner; queued/running owners observe them without signals to unrelated processes. Finish audited outcomes without treating cancellation requests as coverage. Attribute external signal/disconnect/deadline evidence explicitly; an unexplained set token stays unknown.
- Keep legacy review cancellation behind explicit IDs and existing process proof, persisting audit first. Remove opportunistic stale recovery from status/cancel. Add optional expected_request_id/worktree/head/diff_hash guards to all mutating triage paths.
- Expose shared CLI/MCP fields: status scope and list limit; explicit target ID, expected guards, bounded reason/actor; MCP client name is a claim, never authentication. Status returns cancellation attribution and request/review identities. Prepush reservation retains actual caller worktree without changing dedup.

- Publish the historical 24-record unfinished sample as 17 cancellation-token / 7 no-token observations, with unknown actor/cause limits. No historical cleanup or retry.
- Self-review, focused shipped-path suites and separate ResourceWarning sweep; push PR, coordinator runs integrated suite and merges.
